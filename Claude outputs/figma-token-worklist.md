# Figma 토큰 작업 지시서 (2026-09-17)

Figma에서 **변수 세 묶음**을 추가하면 지금 열려 있는 건 중 **넷**이 풀린다.
`#1022`(시맨틱 4색) · `#1051`(버린 답 표시) · `§9.5`(항로선 색) · `#933`(브랜드 판).

- 대상 파일 — `frontend/src/design/tokens/{Light,Dark}.tokens.json` (Figma 내보내기)
- 생성 — `npm run build:tokens` → `src/styles/tokens.generated.css`. **CI가 동기화를 검사**한다

---

## 0. 먼저 알아 두실 것 세 가지

**⑴ 라이트·다크 **양쪽 모두**에 값이 있어야 한다.** 생성기가 키 집합을 대조해
한쪽에만 있으면 **빌드가 실패**한다(`build-tokens.mjs:122`).

```
Light/Dark 토큰 키가 다릅니다.
  Light에만: semantic.warning
```

**⑵ `semantic/warning`은 추가해도 화면이 안 바뀐다.** CSS 별칭
(`--color-warning: var(--cii-c-fill)`)이 아직 옛 값을 가리키므로, 제가 별칭을
바꿔야 반영된다. **안전하게 먼저 넣으셔도 된다.**

**⑶ `semantic/info`는 넣는 순간 지도 항로선 색이 바뀐다.** `FleetMap.tsx`가
`--semantic-info`를 **런타임에 읽고** 있어서다 — 지금은 없는 토큰이라 리터럴
`#1f6feb`로 떨어지는데, 생기는 순간 그 값을 쓴다. `§9.5` 🔒가 원래 요구한 동작이라
**고쳐지는 방향**이지만, 색이 바뀌는 것을 모르고 보시면 놀랄 수 있다.

## 2. `semantic/info` — 넣으면 지도 색이 바뀝니다

`§2.3` 표의 값이다. 확정 N 각주가 *「Info와 Warning 둘 다 출처가 없다」*고 적어 둔
그 둘 중 나머지다.

| 모드 | 값 |
|---|---|
| Light | `#2B6CB0` |
| Dark | `#63A0E0` |

### 이걸 넣으면 함께 정리되는 것

`§9.5` 🔒가 지도 항로선을 `--semantic-info`로 정해 두었는데 **그 토큰이 존재한 적이
없다.** 코드는 규격대로 읽고 언제나 빈 문자열을 받아 리터럴 `#1f6feb`로 떨어진다 —
저장소에서 토큰 밖 색을 쓰는 유일한 지점이고, 라이트·다크가 같은 파랑이다.

토큰이 생기면 **잠긴 규격이 비로소 충족된다.** 항로선이 라이트 `#2b6cb0` /
다크 `#63a0e0`로 바뀐다.

## 3. `brand/*` — ⚠️ **넣기 전에 한 가지 정해 주셔야 합니다**

`#933`의 내용은 「라이트 브랜드 판이 `--color-primary`의 별칭이라 **브랜드 색이
따로 없다**」이다. `§15`는 *「`--brand-*`는 장식용 브랜드 색이고 `--color-primary`
(UI 기본색)와 **다른 축**이다」*라고 정해 두었는데, 값이 없어 같은 축을 쓰고 있다.

### 막히는 지점

2026-09-12 **확정 M**은 **다크 판 배경을 「값」이 아니라 「도출 규칙」**으로 정했다.

> 다크 판 배경은 라이트 브랜드 색을 `--surface-page` 쪽으로 내려 얻는다.

그런데 위 ⑴ 때문에 **Figma에는 다크 값도 반드시 있어야 한다.** 규칙만 두고 값을
비울 수 없다.

### 정해 주실 것

- [ ] **ⓐ 다크도 Figma에 값으로 넣는다** — 확정 M의 규칙으로 계산한 결과를 Figma에
      적어 둔다. 규칙은 `§15`에 「이 값을 어떻게 얻었는가」로 남는다
- [ ] **ⓑ 라이트 브랜드 색만 Figma가 갖고, 다크는 계속 CSS에서 도출한다** —
      이 경우 Figma 변수 이름을 `brand/*`가 아닌 다른 자리에 두거나, 생성기의
      키 대조 규칙을 손봐야 한다(제가 합니다)
- [ ] **ⓒ 이번엔 건너뛴다** — `semantic` 둘만 넣고 브랜드는 다음에

> **권합니다: ⓐ.** Figma가 값을 소유한다는 `§0.2`에 가장 곧다. 확정 M은 「어떻게
> 정할지」의 규칙이지 「런타임에 계산하라」는 뜻이 아니었다고 읽는 편이 자연스럽다.
>
> ⓑ도 가능하지만 생성기에 예외가 하나 생기고, 그 예외는 다음 사람이 이유를 모른다.

### ⓐ로 가신다면 — 미리 재실 것

판 색을 바꾸면 **`§15`가 적어 둔 구조적 경고가 열린다.**

> 보조 문자가 알파라 판 색을 바꾸면 **세 번째로 열린다.** 그때가 불투명 토큰 전환 시점

새 브랜드 색을 정하신 뒤 **판 위에서 가장 약한 글자**(`--auth-brand-muted`)가
그라데이션의 **가장 밝은 끝**에서 `4.5:1` 이상인지 봐야 한다(확정 M의 판정 기준).
값 주시면 제가 실측해 드리겠다 — 지금 값 기준으로는 주 문자 6.61 · 보조 4.75 ·
경계선 6.85로 통과하고 있다.

## 4. 내보내기 · 이후 절차

1. Figma에서 변수 추가 (Light·Dark **양쪽**)
2. DTCG 형식으로 내보내 `frontend/src/design/tokens/Light.tokens.json` ·
   `Dark.tokens.json`을 **덮어쓴다**
   - 생성기는 `$type: "color"`와 `$value.hex`만 읽는다. `components`·`variableId`는
     있어도 되고 없어도 된다
3. 저에게 「내보냈다」고 알려 주시면 제가 이어서 합니다
   - `npm run build:tokens` → 생성 CSS 갱신
   - `--color-warning` · `--color-info` 별칭을 `var(--semantic-*)`로 교체
   - `FleetMap.tsx`의 리터럴 `#1f6feb` 제거
   - `#1051`의 「버린 답」 줄무늬 색 확정 반영 (결정 초안 3절)
   - 전 항목 대비 실측 + 가드 추가 + `§2.3`·`§9.5` 정본 정리
   - `#1022`·`#933`의 `blocked` 해제

**내보내기 전에 값만 알려 주셔도 됩니다** — 대비를 먼저 재서 문제가 있으면
Figma 작업을 두 번 하지 않게 하겠다.
