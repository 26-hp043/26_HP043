# #1431 — MapLibre 2.5D 실험 판정

- 환경: macOS, Chromium (Playwright 1.60.0), Vite 8.3.0, MapLibre GL 6.10.0, 저장소의 PMTiles/Protomaps 자산. `npm run dev -- --host 127.0.0.1`에서 `/experiment-25d.html` 실행.
- 결과: **성공**. pitch 50°에서 PMTiles 배경, 실험 경로선, 선박 마커 1개가 표시됐다. 오른쪽 회전 버튼으로 bearing 0°→30°, 슬라이더로 pitch 50°→55°가 반영됐다. 지도 드래그·휠 확대 후에도 상태는 `지도와 이동 선박 표시 중`이었다. Chromium에서 마커의 화면 위치가 `(722, 184)`→`(708, 199)`로 변했고, 지도 조작 뒤에도 `(709, 238)`→`(714, 264)`로 변했다. [실제 브라우저 스크린샷](./25d-interaction.png).
- 범위: 하네스의 부산→싱가포르 좌표는 **렌더링 검증용 실험 좌표**이며 연간 시뮬레이션 결과의 항차가 아니다. 좌표가 없는 `API_SPEC §6.1`·`§6.3` 결과에서 항로를 추정하지 않는다. 컴포넌트는 별도로 `fetchSeaRoute` 입력도 받지만, 이번 브라우저 확인은 백엔드 없이 실험 좌표로 수행했다. 따라서 SeaRoute API 연결 성공은 검증되지 않았다.
- 장애 처리: PMTiles의 Range/magic 검사 실패, WebGL 컨텍스트 생성 실패, SeaRoute 조회 실패, MapLibre 오류를 화면 상태로 표시한다. 실패한 SeaRoute 선은 만들어 내지 않는다. 언마운트 시 animation frame, marker, MapLibre map을 제거한다.
- 관찰된 경고: 기존 Protomaps 스타일의 일부 sprite·glyph 로드 경고가 콘솔에 남았다. 이번 실험에서는 배경·경로·마커가 표시됐지만, 이 경고는 본 실험의 성공 판정에 포함하지 않았다.
- 당시 판정: MapLibre 2.5D는 기존 지도 자산과 스타일을 재사용하면서 기울기·방위·항로·마커 이동이 작동했다. **이 판정은 기능 가능성에 한정한다.** 이후 사용자 시각 검토에서 미니어처 도시 표현에는 맞지 않는 것으로 확인됐다. 전역 항로 조망에는 MapLibre를 쓰고, 항만 근접 장면은 별도 Three.js 실험으로 검증한다. 이것은 실제 시뮬레이션의 좌표 공급 계약이나 두 화면의 제품 통합을 완료했다는 뜻이 아니다.

## 전체 항로 3D globe 후속 실험

- 전체 항로는 MapLibre globe projection과 기울어진 카메라로 표시하고, 항만 상세는 Three.js 미니어처 장면을 유지한다. 넓은 해역 전체를 고밀도 Three.js 장면으로 만들지 않고 축척에 따라 렌더러의 역할을 나눈다.
- 선박 위치와 항적은 경로점 인덱스가 아니라 누적 대권거리로 보간한다. 사용자는 전체 항로와 선박 추적 카메라를 전환할 수 있고, 부산·싱가포르 표식에서 각 항만 3D 장면으로 진입한다.
- `prefers-reduced-motion` 환경에서는 선박과 카메라의 지속 이동을 멈춘다. globe 또는 WebGL을 사용할 수 없는 환경의 제품 적용 전에는 Mercator 대체 화면과 실패 상태를 별도로 검증해야 한다.
- OSM·Eurostat SeaRoute 데이터는 표시용이다. 항만 진입 가능성·수심·접안 위치를 보증하지 않으며 실제 항차, 항해 계획 또는 CII 계산 거리에 사용하지 않는다.
- 제품 적용 전 실제 항차 좌표 공급 계약, 모바일 GPU 성능, LOD, WebGL 복구, 접근성 및 부산→항로→싱가포르 전환 상태를 추가 검증해야 한다.

재현: `cd frontend && npm run dev -- --host 127.0.0.1` 실행 후 `http://127.0.0.1:5173/experiment-25d.html`을 연다. 이 HTML은 실험 진입점이며 제품 화면에는 연결하지 않았다.
